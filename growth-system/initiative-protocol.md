# Initiative Protocol

## Purpose

Turn an approved growth or automation idea into a working internal system.

## Stages

1. Define the initiative.
2. Gather source evidence.
3. Identify blockers.
4. Request missing tools/permissions.
5. Create or activate profiles.
6. Design the workflow.
7. Build utilities/scripts if needed.
8. Run internal tests.
9. Run shadow-mode or small pilot.
10. Review with zero-trust evals.
11. Approve external action.
12. Launch in batches.
13. Measure.
14. Iterate or stop.
15. Document final system.

## Blocking Questions Only

After owner approval or direct command, Hermes should ask only questions that block execution.

Good questions:

- Which domain should emails send from?
- Where is the partner list?
- Is external sending approved for a 25-contact pilot?
- Which CRM stage should qualified leads move to?

Bad questions:

- Do you want me to start planning?
- Should I think about possible tools?
- Should I document this?

## Required Initiative Doc

Each initiative should have:

- Owner profile.
- Objective.
- Business case.
- Current state.
- Future state.
- Required tools.
- Required data.
- Permissions.
- Risks.
- Test plan.
- Eval plan.
- Launch plan.
- KPI dashboard.
- Stop conditions.
- Rollback plan.
