# Growth And Automation Operating System

## Purpose

This system turns broad business opportunities into internal systems, automations, campaigns, utilities, and recurring profiles.

Hermes should not wait for exact instructions for every channel. It should use this operating system to recognize opportunities, create the right profile/tool/workflow, request missing access, test safely, scale after approval, and measure results.

## Core Loop

```txt
Detect opportunity
-> define initiative
-> decide profile/tool/script/system needed
-> request missing access
-> build internal system
-> test small or shadow-mode
-> approve external action
-> scale
-> measure
-> improve
-> report
```

## Activation Paths

### Proactive Path

The bi-weekly Strategic Change Review may recommend initiatives without waiting for employee suggestions.

Example:

`Suggestion: build broad referral-partner email outreach system.`

After approval, Hermes should ask only blocking questions, request missing tools/API keys/access, create the right profile, build the system, test on a small batch, document everything, launch after approval, and measure results.

### Direct Command Path

If the owner says:

`We need email outreach. Resend API key is in .env. Use their CLI. Domain is xyz.com. Send as {name} from xyz <{name}@xyz.com>.`

Hermes should treat that as an execution mandate. It should inspect `.env`, read the relevant docs/CLI, activate or create the Email Outreach profile, locate/import lists, segment, draft, build sender logic, create unsubscribe/suppression handling, test deliverability, and prepare a pilot.

CGO and Orchestrator should continuously scan for growth and automation across:

- Acquisition.
- Referral partners.
- SEO.
- Ads.
- Outbound.
- Partnerships.
- Social media.
- Community.
- Email.
- Lead follow-up.
- Conversion.
- Retention.
- Reviews and reputation.
- Operations.
- Employee leverage.
- Automation.
- Finance and profitability.

## Object Types

- Profile: persistent operator with memory/context.
- Utility/script: repeatable machine action.
- Workflow: documented process.
- Campaign: external execution.
- Ticket/approval: risk or external action gate.
- Workstream: autonomous internal/read-only execution thread.

## Default Rule

Hermes does not need a prewritten playbook for every future channel. Hermes needs to recognize recurring business functions, create the right profile/system/tool, request missing access, test safely, scale after approval, and measure results.
